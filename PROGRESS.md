### Phase 1 outcomes / decisions

Modules: `cointegration.py` (Engle-Granger via `statsmodels.coint`, OLS hedge ratio **with intercept** by default, `analyze_pair` orchestrator), `spread.py` (`compute_spread` = S1−β·S2−α, `zero_crossings`), `halflife.py` (OU half-life), `zscore.py` (`rolling_zscore` + `latest_zscore`, sample std ddof=1, fixes the prototype's `0.02` approximation), `signals.py` (`evaluate_entry`/`evaluate_exit` with Option-B stop/exit/time-stop). Public API re-exported from `statcore/__init__.py`.
- **Parity strategy (ADR-0007):** validated in **legacy mode** (no intercept, β rounded to 1.29) against the MATIC/STX reference, reproducing the `Spread` and `ZScore` columns to ~1e-9 and matching coint t/p/crit, hedge ratio, and zero_crossings (43); half-life locked at 3.0. The four Option-B changes are asserted in **separate** tests. Reference CSVs committed as hermetic fixtures under `backend/tests/fixtures/` (the `Old Reference Resources/` tree is gitignored).
- **Edge cases:** half-life returns `nan` for non-mean-reverting series (slope `b ≥ −1e-9`, incl. fp-noise trends) and constant spreads (`add_constant(has_constant="add")`); `latest_zscore` returns `nan` on insufficient data / zero-variance windows.
- **Gate (Phase 1) — PASSED locally:** `pytest` 33/33 ✓ (29 statcore + 4 Phase-0 smoke, no regression). Isolated by design — no integration/UI this phase. Note: `np`/`pandas`/`statsmodels` numerics are version-sensitive; parity tests are the early-warning signal (local env: statsmodels 0.14.6, pandas 3.0.3, numpy 2.4.6).

  5. *(doc)* corrected `zero_crossings` docstring re: exact-on-mean behaviour.
  6. *(altitude)* named the coint 5%-critical-value index (`_CRIT_VALUE_5PCT_INDEX`).
  - **Left as-is (judgment):** `latest_zscore` vs `rolling_zscore` formula duplication (the tail form is the efficient path; guarded by a 1e-12 parity test) and the `half_life` `b >= -1e-9` epsilon (documented; rejects only ~7e8-period non-reversion that the 72h cap would reject anyway).

### Phase 3 outcomes / decisions
- **No schema/migration change** — the pair-detail series are computed on demand from live/demo prices + the pair's stored β/α/half-life; nothing new is persisted. The endpoint reads the pair row from `CointScanResult` (so the chart's spread matches the scan that found it) and re-fetches both legs' close history.
- **Backend layering:** new pure-ish builder `marketdata/pair_series.py` (`build_pair_series` → `PairSeries`/`TimePoint`/`Marker` dataclasses) depends only on the `PriceSource` protocol; reuses `statcore.compute_spread`/`rolling_zscore` and **derives entry/exit markers via `statcore.evaluate_entry`/`evaluate_exit`** (single source of truth — no bespoke signal logic). Time stop is omitted from markers (single-window visualisation, not a clock-driven backtest), so markers strictly alternate entry→exit. Z-score warm-up `NaN`s are dropped (invalid in JSON, not plottable).
- **New endpoint** `GET /api/pairs/{base}/{quote}/series?exchange=&mode=` in `routers/pairs.py`: 404 if the pair isn't in the latest scan or the legs share no overlapping history; 503 on DB read failure. Response is chart-ready: `normalized.{base,quote}` (rebased to 100), `spread.{mean,std,series}`, `zscore.{series,markers}`, plus Option-B thresholds (entry 1.5 / exit 0.5 / stop 4.0) for the reference lines. ### Phase 8 outcomes / decisions
- **New package `backend/backtest/`** mirroring the established layering (pure core + thin seams): `windows.py` (pure `build_windows` — tiles `[start,end]` into sliding 90d-scan/30d-trade walk-forward steps, test windows edge-to-edge, partial trailing window dropped), `scan_window.py` (pure per-window cointegration scan — builds an aligned price matrix over the formation window and runs the SAME `statcore.analyze_pair` the live scan uses; the engine offloads it to `asyncio.to_thread`), `report.py` (pure markdown report generator — F8.3), `engine.py` (`BacktestEngine` orchestrator). - **Reuses the Phase-6 tick core + Phase-7 replay primitives verbatim (PLAN §1 single source of truth):** each window's *test* span replays the selected pairs through `simulation.engine.run_tick` (same entry/exit/stop/time-stop, cost model, margin guard, no-reopen-after-stop) over a moving cursor — driven by `replay.historical_feed.align_pairs`/`snapshots_at`/`FundingTable` + an in-memory `replay.working_repo.WorkingSimRepository`, with `now=cursor` so the age clock + funding accrual run on the replay timeline. The **only** Phase-8 addition is the *scan inside each window* (so pairs are re-selected out-of-sample) + strategy CRUD/ranking on top.
- **Window-by-window capital carry + force-close (key design):** positions are force-closed (`END_OF_WINDOW`) at each window boundary because the next window re-scans and may pick different pairs/hedge ratios; capital carries forward. This means **the only state to persist for resume is JSON-serialisable** (resume cursor `processed_windows`, carried `current_capital`, accumulated equity curve / per-window / per-pair / exit-reasons) — there is never an open position straddling a boundary.
- **Subprocess → background task (ADR-0008):** the PRD's "subprocess orchestration" is realised as a FastAPI `BackgroundTasks` sweep + per-window `asyncio.to_thread` (the codebase's CPU-offload idiom — the Phase-2 scan + Phase-7 replay), with in-memory pause/stop flags checked at each window boundary and DB-persisted partial state for resume. Same progress/pause/stop/resume semantics, no IPC/process-management. Pause→resume and stop→terminal-partial are covered deterministically in pytest (pre-arming the control flag after window 0, like the FF cancellation test); the E2E covers create→run→complete→aggregates+report+ranking (a demo run finishes in <1s, too fast to race a mid-run pause in the browser — same reasoning as Phase 7).
